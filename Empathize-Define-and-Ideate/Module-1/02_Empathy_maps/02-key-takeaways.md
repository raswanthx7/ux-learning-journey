# Key Information from an Empathy Map

## Topics Covered

- What key information an empathy map gives a UX designer
- Key information from Says
- Key information from Thinks
- Key information from Does
- Key information from Feels
- How the four sections work together
- Connecting empathy mapping to UX design
- From user research to design opportunities
- Why designers should not jump directly to solutions

---

## 1. What Do We Get from an Empathy Map?

The purpose of an empathy map is not just to fill four boxes.

Each section gives a different type of information about the user.

When we combine all four sections, we get a clearer understanding of:

- The user's problem
- The user's needs
- The user's current behavior
- The user's emotional experience

This information helps the UX designer understand the problem before designing a solution.

---

# 2. Says

## Key Information We Get

From Says, we get:

- Stated problems
- Stated wants
- Stated expectations
- Stated opinions
- Direct complaints

### Main Question

> What is the user directly telling me?

### Example

User says:

> "I forget which jobs I've already applied to."

Key information:

> The user is directly reporting a problem with tracking applications.

---

# 3. Thinks

## Key Information We Get

From Thinks, we get:

- Needs
- Goals
- Motivations
- Concerns
- Wants
- Careful inferences about what the user is trying to achieve

### Main Question

> What does the user need, want, or care about?

### Example

From the user's statements, we may identify:

> Wants one place to keep track of job applications.

Key information:

> The user needs a centralized way to manage applications.

Thinks should be based on evidence from the interview, not unsupported guesses.

---

# 4. Does

## Key Information We Get

From Does, we get:

- Actual behavior
- Habits
- Current workflow
- Current methods
- Workarounds
- Tools the user uses
- Steps the user takes to solve the problem

### Main Question

> How is the user currently dealing with the problem?

### Example

User:

> "I scroll LinkedIn at night and write important job details in Notes."

Key information:

- Uses LinkedIn to find jobs.
- Uses Notes to store information.
- Uses multiple tools to manage the job-search process.

This helps the designer understand the user's existing workflow.

---

# 5. Feels

## Key Information We Get

From Feels, we get:

- Emotional pain points
- Frustration
- Stress
- Worry
- Fear
- Sadness
- Guilt
- Excitement
- Satisfaction

### Main Question

> How is the experience affecting the user emotionally?

### Example

User says:

> "It gets stressful when I have several interviews in the same week because I'm afraid I might miss one."

Key information:

- The user experiences stress.
- The user is afraid of missing an interview.

This tells the designer that managing multiple interviews is not only a functional problem but also an emotional pain point.

---

# 6. The Four Sections Together

Each section gives a different perspective.

| Section | Key Information |
|---|---|
| Says | Stated problems, wants, expectations, opinions |
| Thinks | Needs, goals, motivations, concerns |
| Does | Actual behavior, habits, workflow, workarounds |
| Feels | Emotional pain points, frustrations, fears, satisfaction |

### Simple Shortcut

**Says → What problem are they telling me?**

**Thinks → What do they need or want?**

**Does → How are they currently dealing with it?**

**Feels → How is the problem affecting them emotionally?**

---

# 7. Example: Job Tracker App

Imagine a user says:

> "It gets stressful when I have several interviews in the same week, because I'm afraid I might miss one."

### Says

> "I'm afraid I might miss one."

Information:

> The user directly reports a fear of missing an interview.

### Thinks

> Wants an easier way to manage upcoming interviews.

Information:

> The user needs better organization of interview information.

### Does

The user:

- Checks email for interview details.
- Writes interview dates in Notes.

Information:

> The user currently uses multiple tools to manage interview information.

### Feels

> Stress and fear of missing interviews.

Information:

> Managing several interviews creates emotional stress.

# 8. Connecting Empathy Mapping to UX Design

Empathy mapping helps move from raw interview information toward a better understanding of the user's problem.

The process can be thought of as:

User Interview
-> Empathy Map
-> Identify Problems
-> Understand Needs
-> Identify Pain Points
-> Find Design Opportunities
-> Explore Solutions

---

# 9. Example of the UX Design Connection

### User says:

> "It gets stressful when I have several interviews in the same week, because I'm afraid I might miss one."

### Research information

- Several interviews are difficult to manage.
- The user fears missing an interview.
- The user checks email for interview details.
- The user writes interview dates in Notes.
- The user experiences stress.

### Research insight

Managing multiple interviews is difficult and stressful for the user.

### Design opportunity

Make upcoming interviews easier to see, remember, and manage.

### Possible solutions to explore

- Interview calendar
- Interview reminders
- Today/Upcoming section
- Centralized interview details
- Interview conflict warnings

These are possible solutions, not automatically proven solutions.

---

# 10. Important UX Lesson

Do not jump directly from:

> User has a problem

to:

> Add a feature.

The feature is only a possible solution.

First understand:

1. What exactly is the user's problem?
2. Why is it happening?
3. How does the user currently deal with it?
4. What does the user actually need?
5. How does the problem affect the user?

Then explore possible solutions.

---

# 11. Final Takeaway

The four empathy-map sections help us understand four key areas:

**Says → Problem**

**Thinks → Need**

**Does → Current behavior**

**Feels → Emotional impact**

Together:

> **Problem + Need + Behavior + Emotion = Better understanding of the user**

The goal is not to create an empathy map just for the sake of creating one.

The goal is to use user research to understand the real problem before deciding what to design.
